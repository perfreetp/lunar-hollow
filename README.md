# 机坪保障作业时序动画工具

基于 **three.js + troika-three-text + Vue 3 + TypeScript** 的机位保障作业时序可视化工具。把航班的保障任务按时间展开成三维机位场景动画：拖动时间轴，所有飞机、车辆与地勤人员的位置和朝向都会按插值实时重算。

![overview](tools/shots/71-final-overview.png)

## 功能

- **三维机位场景**：三个机位（A12 / A14 / A16），每个含飞机轮廓、加油车、摆渡车、行李牵引车、行李拖斗和地勤人员，全部由程序化几何体构建，无外部模型依赖。
- **1 分钟刻度时间轴**：从任务开始铺到结束（默认 90 分钟），可点击/拖动直接定位到任意时刻，支持 ¼ 分钟精度拖动与逐分钟键盘步进。
- **纯函数式插值**：任一时刻的对象状态都只由时间 `t` 决定（不累积仿真状态），因此来回拖动、跳转、导入回放都能得到完全一致的结果。
- **路径运动 + 转向对齐**：车辆沿预设多边形路径行驶，在转向点前按航向角平滑转弯（最短弧插值），停靠驻车时间由路径点的 `hold` 控制；航向在段与段之间也做缓入缓出，不会瞬间掉头。
- **岗位文字标签**：地勤人员使用 troika SDF 文字显示岗位（机务 / 加油 / 行李 / 客舱 / 监护 / 牵引…），标签始终朝向相机并按距离保持可读大小。
- **正交 / 透视双视角**：两种相机共享轨道控制器视角，切换时保持观察目标与朝向；`T` 键一键俯视。
- **点击查看任务段**：点击场景中车辆（或左侧车辆列表、时间轴泳道）显示其当前任务段起止时间、当前段进度、整日作业窗口进度与后续任务段。
- **多机位切换保持时间轴位置**：切换机位只改变可见对象与镜头焦点，播放头位置完全不变。
- **JSON 导出 / 导入回放**：导出为带版本号的 JSON（含场景数据与当前播放位置、视角快照），可整体导入恢复；导入前做完整校验并给出可读错误。
- **浏览器本地保存**：场景与播放头保存在 `localStorage`，刷新后自动恢复。
- **遮挡与半透明排序**：实体模型走不透明深度缓冲正确互相遮挡；半透明车辆轮廓 `depthWrite: false` + `depthTest: true`，两遍（背面在前、正面在后）渲染，并按相机距离分带排序，快速拖动时也不会出现混合错序。
- **流畅性**：静态几何按材质合批（每车型 3~5 个 draw call），状态重算为纯函数且分配极少；36 个对象整体重算 <0.2ms，场景约 60~70 个 draw call。

## 快速开始

```bash
npm install
npm run dev          # 开发服务器
npm run build        # 类型检查 + 生产构建
npm run preview      # 预览构建产物（4193 端口）
npm test             # 单元测试（36 项）
npm run verify       # 构建 + 启动预览 + 全量无头浏览器检查
```

首次运行需要本机安装 Chrome 或 Edge（`puppeteer-core` 直接复用系统浏览器，不额外下载）。

### 三维文字字体

岗位标签使用打包的 **Noto Sans SC 子集**（`public/assets/noto-sans-sc-subset.woff`，约 1.4 MB，含 GB2312 一级/二级汉字与常用符号），因此无需联网加载字体。如需重新生成子集（例如要显示生僻字）：

```bash
python tools/build_font_subset.py
```

脚本读取系统的 `NotoSansSC-VF.ttf`，固定字重并裁剪字符集。

## 数据格式

导出的 JSON 是一个带版本号的信封，`scenario` 与 `view` 分别描述场景与播放状态：

```jsonc
{
  "format": "apron-sequence",
  "version": 1,
  "exportedAt": "2026-11-23T06:30:00.000Z",
  "scenario": {
    "version": 1,
    "meta": { "name": "...", "startsAt": "2026-11-23T06:30:00", "duration": 90 },
    "stands": [
      {
        "id": "stand-a12", "label": "A12",
        "origin": { "x": -78, "z": 0 }, "heading": -6,
        "aircraftType": "A320neo", "aircraftLength": 37.6,
        "aircraftWingspan": 35.8, "flight": "MU2351"
      }
    ],
    "actors": [
      {
        "id": "stand-a12:fuel", "kind": "fuelTruck", "name": "加油车 02",
        "stand": "stand-a12", "color": "#e0a12c",
        "segments": [
          {
            "start": 6, "end": 27, "label": "靠机加油",
            "nodes": [
              { "x": -48, "z": 34 },
              { "x": -59, "z": 23 },
              { "x": -67.5, "z": 7, "hold": 6.5 }
            ]
          }
        ]
      }
    ]
  },
  "view": {
    "minute": 23.5, "standId": "stand-a14", "viewMode": "orthographic",
    "camera": { "position": [0, 19.6, 175], "target": [0, 2, 8], "fov": 42 }
  }
}
```

要点：

- **时间单位是分钟**，相对 `startsAt`；`duration` 是时间轴总长。
- **坐标单位是米**：+X 向东，+Z 向南，Y 向上。
- `kind` 取值：`aircraft` / `fuelTruck` / `bus` / `baggageTractor` / `baggageCart` / `groundCrew`。
- `nodes[].hold` 是路径点的驻车分钟数；行进时间按各段弧长比例分配剩余时间，因此任务段总是精确结束于 `end`。
- `facing`（可选，角度）用于把对象朝向钉死（如停放的飞机）；`anchor`（可选）用于非移动对象。
- 导入时接受完整的导出信封，也接受裸的 `scenario` 对象；校验会检查机位引用、时间范围、颜色格式、重复 id 等，并给出可读的中文错误。

## 代码结构

```
src/
  domain/           纯 TypeScript 领域层（无框架、无 GL 依赖）
    model.ts        数据模型、路径调度、姿态插值（核心）
    scenario.ts     演示场景生成（三机位确定性编排）
    io.ts           JSON 校验 / 导出
    clock.ts        时间与时钟格式化
  three/
    sceneController.ts  渲染器、双相机、拾取、每帧姿态应用、轮廓排序、自适应画质
    actorViews.ts       每个对象一个视图：模型、轮廓、选中环
    labels.ts           troika 文字标签层
    apron.ts            地面、标线、灯具、灯光
    models/             程序化几何体（飞机 / 车辆 / 人员 / 共享基元）
    textures.ts         程序化地面纹理
  state/              全局状态与 localStorage 持久化
  components/         Vue 组件（工具栏、时间轴、检视面板、车辆列表、提示）
tools/                字体子集生成、无头浏览器验证脚本、截图
tests/                Vitest 单元测试（插值、转向连续性、导入导出、退化数据）
```

### 关键设计

- **状态是时间的纯函数**。`sampleActor(actor, t)` 是所有对象的唯一真相，`SceneController` 只在时间/选中/场景变化时重算，并在动画帧中统一应用。这让"快速拖动 20+ 对象保持流畅"和"回到同一时刻结果一致"同时成立。
- **转向连续性**。路线被展开为有序的"行驶段 / 驻车段"时间线；每个时间段在末段（约后 38%）朝下段时间点平滑转向，因此角点、驻车掉头、任务段之间的接缝都不会瞬间跳变（有专门的单元测试与浏览器检查）。
- **半透明轮廓排序**。每辆车有合并后的背面/正面两遍轮廓（各自一个 draw call），按相机距离分配 `renderOrder` 分带，保证重叠轮廓从后往前混合；实体模型不写透明，靠深度缓冲正确遮挡轮廓。
- **自适应画质**。检测到软件光栅化（SwiftShader / llvmpipe）时直接关闭阴影并降低像素比；否则在持续掉帧时逐级降级，保证弱设备仍可交互。

## 验证

```bash
npm test        # 36 项单元测试
npm run verify  # 构建 + 5 组无头浏览器检查（共 41 项）并输出截图到 tools/shots
```

**单元测试**覆盖：插值连续性、驻车与行进时间分配、180° 掉头与任务段接缝的航向缓动、退化路线（单点/零长度/零时长）、导入导出往返与校验、时间格式化，以及全时间轴的有限性与航向连续性扫描。

**无头浏览器检查**（`tools/*.mjs`，使用系统 Chrome/Edge）：

| 脚本 | 覆盖内容 |
| --- | --- |
| `browser_check.mjs` | WebGL 挂载、36 对象、时间轴拖动、实体姿态重算耗时与帧预算、透视/正交切换、键盘步进、点击拾取、检视面板、机位切换保持播放头、本地持久化 |
| `visual_check.mjs` | 标签显隐、轮廓渲染顺序与材质标志、姿态确定性（同一时刻结果完全一致）、航向连续性 |
| `occlusion_check.mjs` | **像素级**验证：实体飞机遮挡其身后的半透明轮廓（4304 个机身像素 0 变化，同时轮廓在机身外确有 1412 像素可见） |
| `roundtrip_check.mjs` | JSON 导出 → 刷新 → 真实文件输入导入，播放头/机位/视角/对象数全部恢复，再导出数据一致 |
| `interact_check.mjs` | 空格播放推进时钟、时间轴泳道选中对象、机位标签独立可读、无运行时错误 |

> 无头 Chrome 会把 `requestAnimationFrame` 节流到 ~2Hz，因此帧耗时检查测量的是**应用自身的每帧工作量**（全量重算 + 同步绘制，约 1.5ms），而不是浏览器节拍。
